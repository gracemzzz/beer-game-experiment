The absence of an admitted actor choice is flagged separately; it is never a blank applied answer or a fabricated actor response. **All five primary H1-H4 endpoints measure the model plus the fallback policy**, with a prospective actor-coverage gate before main eligibility.

## Timeout and packet contract

Each game week requests one atomic packet of four literal nonnegative integer orders, in the displayed role order. Valid zero, repeated, identical and extreme admissible orders are retained. There is one opportunity, no revisions, no generated policy/optimizer and no precomputed future-week orders. Each choice follows its current complete public display.

If no complete valid game packet is admitted by the deadline, expire that opportunity. Flag all four current actor choices as absent. For each role, apply its own **previous applied order**, including an earlier carry-forward action; use **4** when no earlier applied order exists in week 1. Every applied order remains a literal nonnegative integer. The same deterministic rule applies to A, B and C. Record the applied source as `carry_forward`, explicitly synthetic. A valid packet received on time uses its exact orders with source `model_on_time`; proximity to the deadline never triggers changes or noise. No random fallback is used.

The receipt deadline closes the opportunity even if expiry is persisted only on the next controller access. Any late literal payload is retained as rejected evidence and cannot replace the applied action. A partial packet cannot supply some roles while the others fall back. Subsequent public history describes the actual applied orders. After a timeout acknowledgment, the actor reads the next public display and chooses for that newly displayed state. It cannot reuse a rejected late answer as an answer to a different state or backfill an expired week.

For a timed-out probe page, apply the **last applied game order for each scenario's displayed role** to all four requested scenario IDs, with source `carry_forward` and the actor-absent flag. Freeze this per-role reference at the end of the 24-week game. Keep it constant across all independent hypothetical scenarios; earlier probe answers never change it. For example, if the retailer's final applied game order is 6, every timed-out retailer probe receives applied answer 6. A timely valid probe page uses its exact four model choices. Every processed probe ID therefore has a numeric applied answer, while its provenance honestly distinguishes an actual timely actor answer from software carry-forward. Freeze `probe_timeout_policy: "last_applied_game_order_by_role"` in every new CASE under the new carry-forward schema. Advance to the next page after recording the applied answers. Do not infer a response from the reading or ask for a late replacement. The fixed scenario order, eight pages and pair identities remain unchanged. After the eight pages, administer the original untimed comprehension questions without answer feedback or coaching.

Invalid on-time payloads, stale/duplicate decision IDs, incomplete displays, unavailable required tools, clock discontinuities or other procedure errors require the actor to stop and report a procedure failure. A rejected on-time submission does not itself reset the clock, advance the state, trigger fallback or permit a repair/retry; the transport may retain its open opportunity in the saved record. Only true expiry triggers the timeout policy, and a later expiry cannot erase or reclassify an earlier procedure failure. A normal acknowledgment of game or probe carry-forward is a continuation event, not a terminal procedure error. Preserve every attempted case and accepted prefix, including a failed preparation or launch. Never replace a failure with a favorable case or silently add another development block. The requirement for a complete numeric applied answer on every processed opportunity does not authorize inventing unpresented future states after a terminal technical failure.

## Endpoints and interpretation

The five matched contrasts and mathematical aggregations remain fixed, but primary H1/H3 now use **applied policy probe answers**, including synthetic carry-forward values. This changes their estimand from actual actor responsiveness to the response of the model-plus-fallback policy. All five primary endpoints share that policy interpretation:

| Endpoint | Fixed calculation | Interpretation under this policy |
|---|---|---|
| H1 | Equal-weight mean of all eight fixed pipeline-pair slopes, `(q_lowP - q_highP) / (P_high - P_low)`, using applied answers; B minus A | Pipeline response of **the model plus the fallback policy**, including every synthetic answer. |
| H2 | Total holding plus backlog cost across four roles and all 24 weeks; B minus A | Outcome of **the model plus the fallback policy**. Requires a complete applied trajectory. |
| H3 | The same eight-pair applied-answer pipeline-response mean; C minus B | Pipeline response of **the model plus the fallback policy**, including every synthetic answer. |
| H4a | Sample variance of 24 applied weekly orders for each role, denominator 23, then mean across four roles; C minus B | Fluctuation of **the model plus the fallback policy**, including every synthetic action. |
| H4b | Each role's applied-order variance divided by the chain's sample external final-customer-demand variance, then mean across roles; C minus B | Bullwhip of **the model plus the fallback policy**. Zero demand variance remains undefined. |

Repeat-last game actions can mechanically reduce order variance and change later states and costs. Probe carry-forward is constant within a role: a pipeline pair whose two answers both fall back has slope zero by construction; a pair with only one fallback mixes an actor answer with a software answer. Consequently none of the primary H1-H4 contrasts can be attributed solely to student cognition or LLM ordering behavior, even if the rule is common across arms. The estimands include treatment-dependent frequency of software intervention. There is no claim that this rule emulates rushed human students. Future effects after week 24 remain unmeasured.

Report actual on-time model orders separately: counts, fraction, zero fraction, range, role/week coverage and observed choices, together with timeout rates and synthetic-action shares by role and arm. A descriptive variance among observed on-time orders, if shown, must be labelled as a selected incomplete subset with its count and covered weeks. It is not a complete-horizon actor-only variance, an H4 replacement or an estimate of unobserved choices. Do not drop synthetic weeks and present the remainder as a full behavioral trajectory. Do not replay earlier choices under a different policy as validated counterfactual model decisions, because the later displayed states would change.

Preserve pair-level and backlog-response diagnostics using applied answers, and report each pair's source pattern. Separately calculate the original actor-only pipeline-response proxy as a **secondary descriptive diagnostic only when all eight fixed pipeline pairs have actual timely actor answers**. If any required actor answer is absent, that secondary aggregate is unavailable; the applied primary remains defined when all applied pairs are complete. Report available actor pair slopes individually without dropping pairs or changing weights to construct an incomplete aggregate. Do not manufacture an actor answer from its applied fallback value. Applied game completion, applied probe completion, actual on-time game/probe coverage, complete actor-only pipeline pairs and comprehension completion are separate fields. No outcome direction or p-value enters endpoint eligibility.

## Bounded development and main gate

Run exactly the three planned full-length development contexts after software checks and the prospective freeze. Audit literal-choice provenance, full public displays, deadline admission, atomic packets, correct previous-applied game fallback, fixed final-game-order probe fallback, honest actor-absent flags and exact physical replay. Record requested/reported settings and transcript attribution. Record all deviations, incomplete endpoints and failure reasons. Report development results descriptively; do not compute or select by main H1-H4 p-values.

The prospective main-readiness gate requires **each of the three planned development cases** to satisfy all of the following, with no pooling of a weak case into another case's coverage:

- Complete 24 applied game weeks and all 32 applied probe answers in the eight fixed pages, with all five policy endpoints numerically defined, and finish all four untimed quiz items.
- Admit valid on-time actual model packets in **at least 18 of 24 game weeks (75%)**. Because the four-role packet is atomic, this is also at least 72 of 96 game orders; partial or rejected packets do not count.
- Admit actual valid on-time model answers for **at least 24 of 32 probes (75%)**, equivalent to **at least six of eight atomic probe pages**. Late, rejected and carry-forward answers do not count as actual coverage.
- Have no unresolved source, timing, full-display, procedure, provenance or replay failures. The C case additionally requires at least **3/4 correct quiz answers**, preserving the original 75% education-comprehension requirement.

Correctly recorded game and probe carry-forward is allowed. Both separate coverage thresholds must pass in every case; averaging game and probe coverage is prohibited. These fixed 75% thresholds are an operational safeguard against predominantly software-produced measurements, not an empirically validated standard of student fidelity or a guarantee against bias. No hypothesis sign, cost size, variance, slope or p-value is used to choose or adjust them. Quiz scores and coverage do not exclude or replace any future main case. Software tests using artificial actors or clocks are labelled synthetic and never counted as participant observations.

Passing this one-block check would show that the revised policy mechanism and fixed measurements met the operational requirements in that bounded block; it would not establish the main completion rate, statistical power, human validity or a desired effect. All policy endpoints can be complete while actual actor-only proxies are unavailable. That distinction must remain visible in every report. If any endpoint, coverage, comprehension or provenance criterion fails, retain the result and keep main blocked. No automatic extra pilots, deadline extensions, coverage-threshold relaxation or modified probe pages are authorized by a failed gate. A scientific change requires another prospective version.

Only after an affirmative documented gate and a separate frozen main plan may main preparation become eligible. That plan must preserve ten matched blocks, separate held-out seeds, one context per arm/block, fixed 24-week scoring, the policy endpoint definitions above, honest actor coverage, all assigned failures and fixed stopping. Freeze sources, materials, seed allocation and randomized launch order. Do not create a main qualification record merely because applied answers can now be completed by software.

If main collection becomes eligible, test the **five primary model-plus-fallback policy contrasts** using matched blocks and two-sided paired randomization inference where assignment supports it; otherwise state the independent symmetric/exchangeable paired-null assumption for sign flips. Use the original Holm family of five endpoints, retain null and opposite effects and report uncertainty. Actor-only diagnostics are not substitute primary tests. No roles/weeks-as-independent tests or significance-based extension are permitted. A primary endpoint unavailable because of a terminal technical failure or undefined variance denominator must retain that status; it cannot silently shrink the multiplicity family or become a complete-case primary claim. With incomplete assigned blocks, report the failure pattern and distinguish any descriptive observed contrast from an all-assigned causal estimate. The 75% thresholds apply only to the prospective development readiness gate. After main assignment, coverage is diagnostic only: retain and flag low-coverage cases and all their fallback weeks; never exclude or replace them. If all ten assigned blocks have complete policy endpoints and valid provenance, policy inference uses all ten regardless of their main actor coverage, subject to the stated assignment/null assumptions. Such inference remains about the model-plus-fallback policy and cannot establish pure student cognition.

## Possible later actual probe-coverage revisions; none selected here

- A separately calibrated longer probe deadline could improve observed completion, while changing the restriction imposed during measurement.
- A common untimed post-game assay could assess responsiveness following the timed game/reading, while removing the current immediate probe-deadline contrast.
- One scenario per page or a shorter validated public display could reduce packet demands, while changing presentation and opportunity structure.

Each option requires new fixed materials, an explicit estimand, a finite prospective feasibility plan and a new fingerprint before use. None licenses fabricated actor answers, selective pair retention or a significance-driven choice. The current development block keeps the original probe bank, four-scenario pages and fixed numerical limits, with the new explicit applied-answer fallback.
