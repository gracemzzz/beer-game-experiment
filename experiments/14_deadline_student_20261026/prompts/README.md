# Experiment 14 prompt and assay contract

- STUDENT_V1.md and STUDENT_V2.md are the only two allowed development wording candidates. Select and freeze one before main collection.
- CONTROL.md and EDUCATION.md contain exactly 170 whitespace-delimited words each. Append only the assigned reading to the selected student task. Do not display treatment hypotheses, researcher protocol, inference code, pairing labels, scoring keys or the other arm's reading.
- probes.json is a top-level list of 32 researcher-authored hypothetical states in fixed presentation order. It contains no orders or expected decisions.
- comprehension.json is a top-level list of four post-behavior questions and private scoring metadata.

## Probe display allowlist

Display only `probe_id`, `role`, `inventory`, `backlog`, `outstanding`, `pipeline_arrivals`, `customer_demand`, `recent_demand_history`, and `shared_inventory`.

Never display `pair_id` or `assay_dimension`. Both are private analysis labels. Pair order and quantity differences are recovered by the analyst from the state values; no positive or optimal decision is encoded.

`pipeline_arrivals` lists outstanding cases arriving in the next three weeks and sums to `outstanding`. Pipeline-pair schedules have the same relative timing allocation and differ in quantity. `customer_demand` and `recent_demand_history` mean incoming demand to the displayed role; the history is oldest to newest. Shared inventory is a mapping with retailer, wholesaler, distributor and factory keys and includes the displayed role's own current inventory. These are hypothetical local accounting scenarios, not complete replayable network snapshots.

Present entries 1-4, 5-8, and so on as eight pages. The order was frozen independently of any model response; paired scenarios do not appear on the same page. Collect four literal nonnegative integer choices keyed by the displayed IDs, with one timed submission per page. No responses are generated by the fixture.

## Comprehension display allowlist

After all gameplay and probe pages, display only `question_id`, `question`, and `choices`. Never display `correct_answer` or `reason`. Collect one A/B/C/D choice per question without a deadline. Feedback comes only after all behavioral measurements and recorded answers. Scores do not determine inclusion in the main sample.

The controller must enforce these allowlists rather than trusting an actor not to read private keys. This folder is researcher preparation; do not give the actor direct file access. The protocol and a separate source fingerprint control launch eligibility. Changing a fixture or reading after main collection begins requires a new scientific version.

The exact preparation bytes and fixture checks are recorded in [PREPARATION_MANIFEST.json](../hypotheses/PREPARATION_MANIFEST.json). That receipt is not a calibration result or permission to launch the main sample.
