# Full student-pilot hypothesis analysis: 11 October 2026

The initial completed student report summarized outcomes but omitted the explicit H1/H2 workflow from `analysis.py` and historical `hypotheses.csv`. The new analysis restores that workflow in a separate, versioned layer. It does not change the completed experiment, raw evidence, prompts, model, high effort, caps, game rules or the five pinned scientific source files.

Original H1 predicts greater supply-line underweighting under a binding decision constraint. The repo outcome is short-minus-adequate mean beta across all four usable role fits in each chain, predicted below zero. Original H2 predicts higher holding/backlog cost; its outcome is short-minus-adequate full scored chain cost, predicted above zero. H2 is checked independently of beta availability. Both use the chain pair as the unit, two-sided sign flips and Holm adjustment across the fixed family of two. A missing hypothesis occupies its family slot conservatively but has no displayed p-value. The inherited eight-pair minimum is a software floor, not power evidence. The new analysis also withholds inference after a failed manipulation screen.

The completed run `student_api_b609eca42866feb0` has one actual pre-outcome selected pair, despite a requested maximum of three. All 288 main decisions are valid and no fallback was committed. Each chain's full cost is 156; the paired H2 difference is zero. All eight role beta fits are unusable, leaving H1 missing. Calibration failed the prespecified actual-token separation criterion, and game output medians were 1,982 versus 1,922. Neither p-values nor confidence bounds can be reported as a valid hypothesis conclusion here. Identical outcomes do not demonstrate equivalence or the absence of a real-student time-pressure effect.

The full report includes original-design mapping, exact hypotheses and estimands, per-hypothesis eligibility, paired outcomes, completion/provenance checks, calibration and game usage, coefficient diagnostics, holding/backlog costs by phase, behavior/service/terminal pipeline checks, and bullwhip window sensitivity. Direct bullwhip is supplementary rather than a newly added third confirmatory hypothesis. Model-choice and late-period windows remain explicitly post-hoc sensitivity checks, with missing ratios for constant denominators.

`src/beergame_study/student_hypotheses.py` reads and verifies saved evidence. `scripts/build_student_hypothesis_report.py` exports Word, Markdown, Excel, CSVs and figures under `reports/<run_id>/` (the completed pilot uses `reports/student_pilot_20261011/`). Analysis source snapshots, original reference snapshots, every raw input hash, external reusable calibration hashes and a zero-additional-charge declaration are saved separately from the scientific run fingerprint. The notebook's final analysis cell needs no key and analyzes the just-run or reviewed saved game.

Validation uses offline synthetic campaigns and mocked clients, never paid experiments. Dedicated tests cover exact sign flips, Holm with missing H1, independent H2 eligibility, incomplete planned samples, sample units, failed gates, one-pair zero differences without p-values or fabricated confidence bounds, source/prompt/state/cost tampering, complete export consistency, and partial-scoring reports. The README records the final test counts, notebook checks and artifact links. Existing outcome and raw files remain unchanged.

The analysis is explicitly post-hoc. It does not create a prospective human protocol, validate the UB persona, validate information overload, convert human seconds to tokens, or guarantee power. Preserve historical none-effort/two-call results separately. Future scientific changes require a new protocol/fingerprint and prospectively defined calibration, identification and sample planning; future paid runs require separate authorization and a hard cap.
