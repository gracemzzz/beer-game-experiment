# Four reusable website prompts — protocol v4

1. This is a new exploratory joint-context collection, requested on 25 October 2026. It preserves the earlier separated-arm v3 pilots and main preparation unchanged.
2. One reusable prompt per requested model runs three conditions in one fresh chat: 10 chains per condition, four fictional roles per chain, 24 Python-maintained weeks. One returned batch has 2,880 weekly orders and 480 final probe choices, plus A's initial proposals.
3. The statistical cluster is the fresh chat, not its 30 chain instances or 120 fictional identities. The convenience of one prompt comes with possible cross-condition learning and education leakage. These results cannot establish isolated student education effects or a binding human deadline.
4. No new observations or significant findings exist when this package is prepared. No prompt contains a desired effect direction, required variability, target p-value, or forced ordering behavior.

## Collection fixed before new observations

Requested models: GPT-6 Astra, GPT-6.1 Sol, GPT-6 Luna, Claude Sonnet 5.5. Use a code-enabled interface; the current OpenAI documentation places Sol/Luna in Work/Codex rather than ordinary Chat. Select high reasoning for the three GPTs where offered, and thinking enabled/high where offered for Claude. Record the actual selected labels; keep them fixed within each model's collection. Interface settings are not verified API settings and reasoning labels are not necessarily equivalent across providers. Do not use autonomous delegation/Ultra for this protocol. No temperature intervention is made.

First collect one file from each model. Continue with the SAME prompt in fresh chats; no new wording or case IDs are needed. The helper assigns a UUID, demand seed and randomized order of the three conditions. The three conditions share the same demand paths and profile assignments within a batch; model batches have independent seeds, so there is no paired cross-model test. Do not reroll seeds or select successful-looking outputs.

Fixed target: 40 attempted fresh chats per model, regardless of observed signs/p-values, including partial/failed attempts. Preserve every attempt and its order; never replace failures silently. Reuse of one conversation is not a fresh replication. Prefixes of 1, 2, 5, 10, 20, 40 reviewed complete chat batches are descriptive available-case summaries, with all incomplete attempts retained in the intake log. An incomplete/failed collection remains provisional even if complete-case p-values are small. No significance-driven extension is authorized by this plan; larger samples require a new prospective plan.

One batch = 10 chains per condition, 30 total chain instances. At 2/5/10/20/40 batches there are 20/50/100/200/400 chains per condition and 60/150/300/600/1,200 total instances per model. This does not create 1,200 independent model responses. Separate fresh chats are assumed independent only conditional on unchanged model/settings and documented collection; common service/model changes may violate that assumption.

## Treatments and physical game

Use the unmodified v3 physical controller, with a new coordinator and fingerprint. A receives the 127-word control reading and an initial decision followed by a separate review interaction; B receives the control reading and commits initial decisions; C receives the matched 127-word causal education reading and commits initial decisions. All states share role inventories. The randomly chosen condition order is preserved for carryover diagnostics. Counterbalancing does not erase a shared context. Conditions finish sequentially to bound displayed context; each weekly decision follows its own Python display.

The restriction is actually enforced as one versus two submission opportunities. Hidden model computation, time and tokens are NOT capped, measured or equated to human time. Requesting a short response does not create a binding cognitive deadline. No programmed order policy, random-order generator, fabricated missing decisions, forced positive order, or target maximum is allowed. Python generates physical states and random demand only. Students are fictional second-year University at Buffalo business students with four ordinary-coursework profiles; no actual student data validates them.

## Outcomes and tests

H1: B minus A in pipeline-response sensitivity, expected negative. H2: B minus A in cumulative holding/backlog costs, expected positive. H3: C minus B in pipeline-response sensitivity, expected positive. H4a/b: C minus B in individual order variance and bullwhip, expected negative. These directions are analyst-side only, absent from decision prompts.

Sensitivity uses existing matched hypothetical states: (order at pipeline 8 minus order at pipeline 32)/24, averaged across roles, chains and backlog 40/64. It measures responsiveness to outstanding replenishment, not an identified normative underweighting coefficient. Identical sensitivity 1 is a real null contrast, not a software failure. Extra probes are not extra independent participants.

Cost is the chain sum over 24 weeks, then averaged across 10 chains. H4a is each role's sample order variance (ddof 1), averaged across roles/chains; H4b divides each role variance by its chain's external-customer-demand variance, then averages. Zero demand variance remains undefined. Secondary measurements: backlog responsiveness, zero-order fractions, initial-to-final revisions, condition order, public controller intervals and completeness. They do not replace primary outcomes after inspection. Controller intervals include tools and infrastructure, not just thinking.

For each chat compute paired contrasts after averaging its chains. At least two reviewed batches are needed to calculate exploratory two-sided paired sign-flip p-values and pointwise block-bootstrap intervals. Independence and symmetric paired differences are assumptions, not consequences of UUIDs. Holm correction retains all 20 endpoints (five × four models); H4 requires both components to meet the criterion in the predicted direction. Contradictory signs and zeros stay in the report. Sweeps are descriptive, not repeated confirmatory tests. The fixed full-sample analysis remains exploratory for joint-context AI responses, with no claim to literal H1–H4 verification in people.

Planning curves assume normal paired chat differences with standardized effect d=0/.2/.3/.5/.8 and a conservative two-sided alpha .05/20. SciPy's noncentral t distribution supplies an approximate power calculation; it is not the exact sign-flip test's power. Report 80%/90% detection probabilities, never a guaranteed significance threshold. More data cannot reliably reveal an effect whose true value is zero. Old v3 pilot variance is not used to predict this new design's required sample size.

## Provenance and stopping

Retain exact prompt/helper hashes, raw JSON, actual model/mode, complete chat/tool transcript, all errors and deviations. JSON replay proves arithmetic and sequence consistency only. A human/agent reviewer must verify literal choices following displayed states, separate A reconsideration interactions, no ordering program, no source/private-state inspection, a fresh chat, and unchanged settings. A source exposure or missing transcript blocks inferential eligibility; preserve the output for descriptive review. Do not substitute generated execution summaries for the authentic transcript. Inspection restrictions are procedural, not a security boundary.

If the platform stops mid-run, return the partial JSON and transcript. Continue only the same run in the same chat if the controller still exists; never reconstruct missing decisions or count continuation as a new chat. Four prompt launches are a collection start, not a completed 40-batch study. No API calls, credentials or ledger mutations occur. Website subscription/usage limits may still apply; the existing cumulative API cap stays $5.
