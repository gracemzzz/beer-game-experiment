# Pivot v2: independent weekly runs and restricted reconsideration

**Status: development protocol, 25 October 2026. No new API observations collected.** This is a new version inside experiment 13, separate from the completed `weekly_api_c64d75aa3a03356f` sample. Freeze the final source, prompts, plan, settings, rates and sample before any held-out collection. Development responses never enter the held-out analysis.

## 1. What this can test

The user's H1–H4 concern a **binding decision-time constraint**. Writing “10 seconds” in a prompt does not impose that constraint. This version operationalizes an AI **restriction on reconsideration opportunities**: restricted arms commit their first valid order response; the adequate arm receives one additional model call to reconsider the same display before orders are committed. All calls use high reasoning effort. Python records actual latency, usage and whether reconsideration changes an order.

This is an experimentally imposed computational opportunity difference. It is not a calibrated wall-clock deadline, proof of subjective pressure, or a literal test of human deadline effects. If the restricted arm would have chosen the same orders after reconsideration, that is a null manipulation response, not an error to repair. A literal deadline study requires a separately versioned, prospectively calibrated and measured deadline design; aborted/truncated responses cannot be silently converted into decisions.

## 2. Arms, identities and game

| Arm | Lecture | Decision opportunities per week |
| --- | --- | --- |
| A | Matched control | Initial response, then one reconsideration response |
| B | Matched control | Initial response committed |
| C | Causal supply-chain education | Initial response committed |

Each arm has its own request context. No request contains another arm's decisions or outcomes. A matched block shares customer-demand and profile seeds across arms and models, but no generated answers. All prompts describe fictional second-year University at Buffalo business students. These identities are not real enrolled students. Profiles allow differing backgrounds without prescribing pipeline neglect, oscillations, a treatment response, an order floor or artificial diversity. With no human comparison data, student fidelity is unvalidated.

Python maintains the unchanged four-role physical game for **24 scored weeks**. The model supplies orders only. Customer demand is frozen locally, with future realizations and the scoring horizon withheld from the decision prompt. Every role receives its own state and the four current inventories. Batched roles/chains can see the request's other displays: only arm isolation is enforced, not independent person-level cognition.

Default is **one chain per arm per independent block**. More chains can be batched within a block for economy; their outcomes are first averaged inside that block/arm. They do not increase the independent sample size. Distinct blocks have distinct seeds and stateless request streams. Calls over weeks within a block are dependent. Shared models/providers can still create dependence across nominally separate generations; claims are conditional on these models, prompts and collection period, not a random sample of humans or models.

## 3. Models and settings

Proposed models: `gpt-6-luna`, `gpt-6.1-sol`, `gpt-6-astra`, `claude-sonnet-5-5`. Requested and returned identifiers are recorded separately; unsupported/unavailable models are recorded as failures, not substituted after seeing outcomes. Official model documentation was checked on 25 October 2026. [Luna](https://developers.openai.com/api/docs/models/gpt-6-luna), [Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol), [Astra](https://developers.openai.com/api/docs/models/gpt-6-astra), [Sonnet](https://platform.claude.com/docs/en/models/sonnet-5-5/overview).

Use **high effort for every call and arm**. OpenAI uses `reasoning.effort=high`; Claude uses adaptive thinking and `output_config.effort=high`. These provider controls do not imply identical computation. No temperature override: provider support differs and changing temperature cannot validate a fictional persona. Default output allowance is **8,192 tokens including hidden reasoning**, identical between arms. This generous allowance protects complete structured decisions; it is not the intervention. A small output cap that eliminates JSON is a failure, not usable evidence of a hurried order. Freeze a different allowance only after a bounded format pilot, never based on hypothesis effects.

## 4. Outcomes and contrasts

All outcomes come from literal accepted choices and Python state replay. Missing orders remain missing. Zero, constant, extreme admissible, null and opposite responses remain valid observations.

| Hypothesis | Operational endpoint | Contrast and predicted direction |
| --- | --- | --- |
| H1 | Matched-state pipeline sensitivity | B − A, negative |
| H2 | Sum of holding/backlog costs across roles and 24 weeks; average across chains within a block | B − A, positive |
| H3 | Same pipeline sensitivity | C − B, positive |
| H4a | Average of four roles' sample variances of 24 weekly orders; then chain mean | C − B, negative |
| H4b | Each role's order variance divided by that chain's external customer-demand variance; then role/chain mean | C − B, negative |

The separate pipeline assay changes only outstanding replenishment in matched displays. Sensitivity is `(order_low_pipeline − order_high_pipeline) / pipeline_difference`. Retain role/display-level answers, floor counts and backlog-response checks. A higher sensitivity is not automatically optimal; lower sensitivity alone does not identify structural underweighting. A structural behavioral model or justified normative benchmark would be needed for that stronger claim. Report H1/H3 as **pipeline-sensitivity analogues**, with the original substantive hypotheses still unverified.

H4a/b concern **order variation and bullwhip**, not the historical education study's cost H4. Use all 24 weeks, sample variance (ddof=1), external demand as the H4b denominator, and undefined rather than zero when demand variance is zero. Since paired arms share the demand path, H4a/b are closely related, not two independent replications of an effect. Do not add post-horizon costs to H2; report terminal stock/backlog/commitments separately.

## 5. Sample-size sweep and inference

Prepare a fixed maximum of **40 matched independent blocks per model**; show fixed prefixes at **10, 20 and 40 blocks**. With one chain/arm/block these mean 30, 60 and 120 chains/model respectively, and 120, 240 and 480 across all four models. A label such as “20 chains” must never mean 20 independent replications if there are fewer independently generated blocks.

The 10/20/40 prefix plots are interim descriptive sensitivity displays, not three chances to stop at significance. The final confirmatory analysis would use the prospectively funded fixed maximum. Do not extend the sample after examining p-values. If the budget cannot cover that maximum, freeze a smaller design before held-out collection and label its power limitations. Missing/failed arms and complete-pair denominators stay visible. Differential failures can bias complete-case contrasts; do not claim an intention-to-treat effect from complete cases alone.

Analyze block-level paired differences, two-sided sign-flip tests under the independent, symmetric paired-null assumption, and deterministic block bootstrap intervals. Confidence intervals are pointwise estimation intervals, not multiplicity-adjusted significance evidence. Use five-endpoint Holm adjustment within a model; a cross-model claim requires the full 20-test family. An opposite-direction significant difference is not support. Sharing demand seeds across models induces cross-model dependence; Holm remains applicable without an independence requirement, but do not treat four models as four independent human studies.

Power planning curves use assumed standardized effects and a paired-t approximation, clearly marked **planning, not observed data**. Neither the curves nor artificial software controls establish that these models exhibit a nonzero effect.

## 7. Research basis

- [Sterman (1989), Management Science](https://pubsonline.informs.org/doi/10.1287/mnsc.35.3.321): dynamic inventory decisions and feedback provide the rationale for measuring pipeline response rather than relying only on total costs.
- [Croson and Donohue replication materials](https://msreplication.utdallas.edu/croson-donohue-2006/): a student experiment requires explicit stimuli, independent sampling and an interpretable information-sharing intervention. The replication page reports partial replication, so prior literature does not guarantee the present signs.
- [Wu and Katok (2006), Journal of Operations Management](https://www.sciencedirect.com/science/article/pii/S0272696305001634): training and communication are distinct design components; the abstract does not justify assuming a lecture by itself must improve supply-chain performance.
- [Croson, Donohue, Katok and Sterman, author abstract](https://www.mit.edu/~jsterman/Order_stability.html): mechanisms that reduce amplification need not reduce pipeline underweighting. Preserve this distinction in H3/H4 interpretation.

These sources motivate the design; the proposed AI manipulation and its student fidelity have not been validated by those papers.
